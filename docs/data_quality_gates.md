# Data Quality Gates & Validation Policies

## 1. Objectives & Architectural Role

This document defines the strict data quality gates that must execute before any synthetic event traces or ML training sets are ingested into anomaly detection models or evaluation pipelines.

**Core Pipeline Principle:**
- Raw Traffic Captures / Telemetry -> Normalization & Event Schema
- Event Schema -> Data Quality Gates Validation
- If Quality Gates Pass -> Train / Evaluate / Infer
- If Any Critical Gate Fails -> Pipeline Rejection (Hard Abort)

Quality gates are non-optional security controls to guarantee synthetic trace fidelity and model reliability.

---

## 2. Rationale & Error Surface

In machine learning-assisted traffic synthesis and defense evaluation, the dominant failure mode is data corruption rather than model capacity:
- Datasets such as CICIDS2017 are flow-level aggregations, not native event sequences.
- Data leakage across train/validation/test partitions easily produces artificial overconfidence.
- Heuristic label mappings can misclassify complex application states.
- Synthetic event expansion may appear plausible while violating underlying TCP/IP protocol invariants.

---

## 3. Quality Gate Suite

### Gate 1 - Schema Conformance Gate
- Verifies all mandatory envelope fields (`schema_version`, `dataset_origin`, `trace_id`, `source_file`, `split_group_id`, `session_id`, `events`).
- **Failure Condition:** Any mandatory envelope field missing or unpopulated.

### Gate 2 - Enumeration & Value Boundary Gate
- Asserts strict adherence to supported enumerations: `protocol`, `label`, `event_type`, `delay_bucket`, `method`, `path_bucket`, `header_profile`, and `payload_class`.
- **Failure Condition:** Unregistered enumeration strings detected.

### Gate 3 - Sequence Grammar Gate
- Verifies stateful sequence ordering: Sessions must begin with connection handshake states (`SYN` / `CONNECT`) and conclude with valid terminations (`FIN` / `RST` / `CLOSE`).
- **Failure Condition:** Impossible protocol state transitions.

### Gate 4 - Protocol Semantic Consistency Gate
- Validates field cross-coherence (e.g., HTTP methods must not exist on pure UDP flows; TCP sequence increments must match payload lengths).
- **Failure Condition:** Inconsistent cross-layer header combinations.

### Gate 5 - Label Mapping Transparency Gate
- Inspects origin labels to ensure unambiguous mapping into standard categories (`benign`, `stress_stream`, `volumetric`, `slow_exhaustion`, `anomalous`).
- **Failure Condition:** Ambiguous or overlapping class mappings.

### Gate 6 - Partition Coverage Gate
- Verifies that validation and test partitions do not reference unseen protocol schemas or feature distributions not present in training sets.
- **Failure Condition:** Critical feature divergence between splits.

### Gate 7 - Split Leakage Prevention Gate
- Strictly isolates `split_group_id` / source IP addresses so that flows from the same physical session never cross partition boundaries.
- **Failure Condition:** Shared session identifiers across training and evaluation splits.

### Gate 8 - Distribution Stability Gate
- Measures statistical divergence (Wasserstein distance / KL divergence) across baseline and perturbed feature distributions.
- **Failure Condition:** Severe class collapse or uncharacteristic variance.

### Gate 9 - Session Integrity Gate
- Enforces monotonically increasing timestamps and sensible inter-arrival bounds within individual flow traces.
- **Failure Condition:** Time inversions or negative deltas.

### Gate 10 - Heuristic Inflation Gate
- Detects artificially inflated token lengths or repetitive dummy payloads generated by naive synthetic fuzzers.
- **Failure Condition:** Repetition entropy falling below realistic thresholds.

### Gate 11 - Metric Nullability Gate
- Checks for NaN, Infinity, negative duration, or floating-point division errors in timing calculations.
- **Failure Condition:** Any non-finite metric encountered.

### Gate 12 - Provenance & Traceability Gate
- Validates cryptographic SHA-256 source hash and git commit provenance attached to every training artifact.
- **Failure Condition:** Unsigned or unverifiable data origin.

### Gate 13 - Export Contract Gate
- Ensures serialized JSON/Parquet outputs conform to downstream ML engine ingestion contracts.
- **Failure Condition:** Malformed serialization.

---

## 4. Enforcement Policy & Exit Codes

| Severity Tier | Policy Behavior | Pipeline Action |
| :--- | :--- | :--- |
| **P0 (Critical)** | Schema, Enum, Leakage, Grammar | Immediate hard exit (`exit code 1`). Build failure. |
| **P1 (High)** | Distribution, Protocol Consistency | Warning logged; blocked from production artifacts. |
| **P2 (Medium)** | Coverage, Inflation | Warning logged; included in evaluation report. |
